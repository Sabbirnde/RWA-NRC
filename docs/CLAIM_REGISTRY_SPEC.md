# Claim Registry & Economic Claim Specification

> **Frozen Baseline Architecture Segment**:  
> `ERC-7540 Async Vault ──> Claim Registry`

---

## 1. Objective & Architecture Representation Choice

`ClaimRegistry.sol` represents the economic settlement claim generated by `AsyncRWAVault.sol` upon asynchronous deposit request creation.

* **Representation Choice**: Internal specialized registry contract instead of heavy ERC-721/ERC-20 wrappers. This minimizes gas overhead during deposit requests while maintaining 100% deterministic mapping between vault request IDs and economic claim entitlements.

---

## 2. Canonical Claim Struct & Field Definitions

```solidity
enum ClaimStatus { Active, Listed, Transferred, Settled, Cancelled, Invalidated }

struct Claim {
    uint256 claimId;       // Auto-incrementing unique claim identifier
    string requestId;      // Associated AsyncRWAVault deposit request ID (e.g. "REQ-0001")
    string assetId;        // Underlying RWA asset identifier (e.g. "RWA-001")
    address owner;         // Current legal owner of the settlement claim entitlement
    uint256 faceValue;     // Underlying asset amount locked in vault (USDC 6 decimals)
    ClaimStatus status;    // Current status: Active, Listed, Transferred, Settled, Cancelled, Invalidated
    uint256 claimableAt;   // Epoch timestamp when claim was created
    uint256 expiresAt;     // Expiration timestamp (e.g. 30 days after creation)
    bytes32 metadataHash;  // SHA-256 / keccak256 hash of claim parameters
    uint256 createdAt;     // Creation timestamp
    uint256 updatedAt;     // Last status / ownership update timestamp
}
```

## 3. Claim Lifecycle & State Transitions

```
 Vault Deposit Request (REQ-0001)
               │
               ▼
       [ Claim Created ] ──> Status: Active
               │
               ▼
         [ Claimable ] ──> Status: Listed / Transferred
               │
               ▼
          [ Settled ] ──> Status: Settled (Finalized Shares Minted)
```

* **Failure / Termination Paths**:
  - `Cancelled`: Request rejected or cancelled prior to settlement.
  - `Invalidated`: Vault emergency pause or attestation invalidation.

---

## 4. Proven Security Invariants

1. **Duplicate Claim Prevention Invariant**:
   `1 request_id ==> EXACTLY 1 claim_id`  
   *Proof*: `createClaim()` asserts `requestIdToClaimId[requestId] == 0`. Subsequent calls revert `ClaimAlreadyExists()`.

2. **No Double Settlement Invariant**:
   `claim.status == ClaimStatus.Settled ==> markClaimSettled() REVERTS`  
   *Proof*: `markClaimSettled()` asserts `claim.status != ClaimStatus.Settled`, reverting `AlreadyClaimed()`.

3. **Obligation Cap Invariant**:
   `claim.faceValue == deposit.amount`  
   *Proof*: `AsyncRWAVault.sol` passes exact deposit `amount` as `faceValue` when calling `createClaim()`. Reverts `InvalidAmount()` if zero.

4. **Unambiguous Ownership Invariant**:
   `getClaimOwner(claimId)` returns exact current owner or reverts `ClaimNotFound()`.

5. **Vault & Market Access Control Invariant**:
   Only authorized `vault` and `claimMarket` addresses (plus contract owner) can alter claim status or ownership (`onlyAuthorized` modifier).
