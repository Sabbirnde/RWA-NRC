# Canonical RWA Data Layer & Acquisition Specification

> **Frozen Baseline Architecture Segment**:  
> `External / RWA Data ──> Firecrawl / Mock API ──> RWA Middleware`

---

## 1. Canonical RWA Data Schema (`CanonicalRWAObservation`)

The Canonical RWA Data Observation schema represents the standardized, deterministic payload generated by external data acquisition providers before entering the RWA Middleware validation engine:

```typescript
export interface CanonicalRWAObservation {
  observationId: string; // Unique observation identifier (e.g. "obs-RWA-001-1786198000")
  assetId: string; // Canonical asset ticker/identifier (e.g. "RWA-001")
  assetType: string; // Asset category ("TREASURY", "CORPORATE_BOND", "REAL_ESTATE")
  valuation: number; // Current NAV in USD (e.g. 1,002,500 for $1,002,500)
  yieldRate: number; // Annualized yield percentage (e.g. 5.20%)
  currency: string; // Currency ISO code ("USD")
  timestamp: number; // Unix epoch timestamp (seconds)
  source: string; // Data provider provenance ("Firecrawl Live Ingestion", "Mock RWA Provider")
  sourceUrl: string; // Exact URL extracted (e.g. "https://treasury.gov/rates/daily-treasury-yield")
  jurisdiction: string; // Legal jurisdiction ISO ("US")
  status: "VERIFIED" | "PENDING" | "REJECTED" | "UNVERIFIED";
  custodyStatus: "VERIFIED" | "UNVERIFIED" | "PENDING";
  settlementStatus: "SETTLED" | "PENDING" | "REJECTED";
  riskStatus: "PASS" | "FAIL" | "LOW" | "ELEVATED";
  metadata: Record<string, unknown>; // Domain specific metadata (CUSIP, Issuer, etc.)
  metadataHash: string; // SHA-256 hash of canonicalized metadata JSON
  rawHash: string; // SHA-256 hash of raw extracted payload
}
```

## 2. Trust Boundary Architecture

```
┌─────────────────────────────────────────────────────────┐
│              UNTRUSTED EXTERNAL DOMAIN                  │
│  Treasury.gov ──> Web Scraper ──> Firecrawl API         │
└──────────────────────────┬──────────────────────────────┘
                           │ Raw Unverified Feeds (HTTP)
                           ▼
┌─────────────────────────────────────────────────────────┐
│            TRUST BOUNDARY (RWA MIDDLEWARE)              │
│  1. Domain Allowlist Check (e.g. treasury.gov, sec.gov) │
│  2. Payload Hash Generation (metadataHash, rawHash)      │
│  3. 10-Point Structural Validation Checklist            │
│  4. Freshness Assertion (MAX_DATA_AGE <= 300s)          │
│  5. Risk Engine Posture Evaluation (PASS / FAIL)        │
└──────────────────────────┬──────────────────────────────┘
                           │ Validated Observation
                           ▼
               EIP-712 Attestation Signing
```

* **Core Rule**: Scraped data from Firecrawl is treated as **untrusted external input**. Firecrawl can **NEVER** directly interact with or update smart contracts on-chain (`Firecrawl ⇏ Blockchain`).

---

## 3. Validation & Defense Controls

1. **Domain Allowlisting**: Only predefined domains (`treasury.gov`, `federalreserve.gov`, `sec.gov`) are processed. Requests targeting un-whitelisted domains are immediately rejected (`status: "REJECTED"`).
2. **Freshness Assertions**: Observations older than `MAX_DATA_AGE_SECONDS` (default: 300 seconds / 5 minutes) fail validation with `STALE_DATA`.
3. **Timeout & Retries**: Firecrawl calls use an `AbortController` timeout of 5,000ms. On network timeout or rate limit (HTTP 429), ingestion fails closed to the fallback provider.
4. **Cryptographic Hashing**: Every observation computes `rawHash` and `metadataHash` to prevent tampering across middleware transitions.

---

## 4. Failure Modes & Fail-Closed Behavior

| Failure Mode | Root Cause | Middleware Safety Behavior | Result |
|---|---|---|---|
| **Disallowed Domain** | Extracted URL not in allowlist | Rejects observation with `REJECTED` status | **Delay Settlement** |
| **Malformed Payload** | NAV is non-numeric or <= 0 | Fails validation with `INVALID_NAV` | **Delay Settlement** |
| **Stale / Expired Data** | `now - timestamp > 300s` | Fails validation with `STALE_DATA` | **Delay Settlement** |
| **Timeout / Rate Limit** | Firecrawl API timeout > 5s | Gracefully falls back to Mock Provider fail-closed state | **Delay Settlement** |
| **Unverified Custody** | Asset custody status != `VERIFIED` | Fails validation with `CUSTODY_NOT_VERIFIED` | **Delay Settlement** |

> 🚨 **Paramount Rule**: *WHEN DATA IS UNCERTAIN, DELAY SETTLEMENT. Never: uncertain data → settle anyway.*

## 5. Deterministic Mock RWA Provider Simulation Modes

For automated testing and local execution, `MockRWAProvider` implements 8 simulation modes:

1. `valid`: Perfect data, current timestamp, `PASS` risk status.
2. `invalid`: Malformed negative NAV (-100), `REJECTED` custody status.
3. `stale`: Timestamp set to 1 hour in the past (> 300s threshold).
4. `missing`: Throws `Asset not found` exception.
5. `changed_valuation`: Reflects sudden 5% valuation shift ($1.05M).
6. `conflicting`: Custody `UNVERIFIED` and settlement status `REJECTED`.
7. `duplicate_observation`: Reuses fixed `observationId` for deduplication tests.
8. `expired`: Expired timestamp failing freshness threshold.
