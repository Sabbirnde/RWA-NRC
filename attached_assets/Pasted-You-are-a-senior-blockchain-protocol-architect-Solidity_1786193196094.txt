==================================================
2. CORE PROBLEM
==================================================

Traditional ERC-4626/static vaults assume atomic and synchronous execution:

Deposit → Immediate shares
Redeem → Immediate assets

This assumption breaks for tokenized RWAs because real-world assets have:

- asynchronous settlement
- delayed NAV updates
- external interest rates
- credit-risk changes
- custody/issuer verification
- multi-day settlement
- external data dependencies

The system must solve three primary problems:

1. Yield/valuation drag caused by settlement latency and stale state.
2. Transaction-ordering/arbitrage risk around state updates.
3. Execution/state failures caused by stale, invalid, manipulated, or unavailable external data.

The project should demonstrate that an asynchronous vault architecture is better suited to RWA settlement than a static synchronous vault.

8. ASYNCHRONOUS STATE MACHINE
==================================================

Implement explicit state transitions.

Deposit lifecycle:

REQUESTED
    ↓
PENDING_VERIFICATION
    ↓
VERIFIED
    ↓
PENDING_SETTLEMENT
    ↓
SETTLED
    ↓
CLAIMABLE
    ↓
FINALIZED

Failure path:

ANY VALID STATE
    ↓
EXCEPTION
    ↓
PAUSED / RECOVERY
    ↓
RESOLVED

Do not allow arbitrary state transitions.

Define allowed transitions in Solidity.

Example:

REQUESTED → PENDING_VERIFICATION = valid

PENDING_VERIFICATION → SETTLED = invalid

PENDING_SETTLEMENT → SETTLED = valid

SETTLED → CLAIMABLE = valid

CLAIMABLE → FINALIZED = valid

FINALIZED → CLAIMABLE = invalid
